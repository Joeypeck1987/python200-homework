I searched for Software Engineer, Junior Software Engineer, Associate Software Engineer, and Data Engineer. Related titles included full-stack engineer, Data Engineer II, and staff software engineer. The responsibilities and qualifications explain more than the title alone.

I would search both labels and read the actual requirements. A web developer search emphasizes websites and browser interfaces; the software engineer examples also include platforms, mobile work, and data systems. These are overlapping search terms rather than universal job categories.

## 2. Search by language

Searching for Python brought up data engineering and application engineering. In [Amazon's finance data engineering role](https://www.amazon.jobs/en/jobs/10557689/data-engineer-ww-ops-finance-s-a), Python appears with SQL, AWS, ETL, and data modeling. [Splice](https://job-boards.greenhouse.io/splice/jobs/8707299002) pairs Python with SQL, BigQuery, SQLMesh, and orchestration tools. This suggests that a useful next step after Python is SQL and practical database work.

JavaScript searches also surfaced TypeScript and React. [Veeva](https://jobs.lever.co/veeva/907dccc7-0052-41e9-920b-28e5ba6aaba9) lists JavaScript, React, and TypeScript for frontend work; [Walmart](https://careers.walmart.com/us/en/jobs/R-2606412) lists these technologies alongside API design and cloud architecture. Knowing JavaScript alone is a starting point, while employers may expect a framework and typed application code as well.

## 3. Search by cloud, AI, and frontend

Cloud searches introduced AWS services, containers, microservices, deployment, and monitoring. AI searches introduced model integration, automation, and orchestration. Frontend searches introduced React, TypeScript, interfaces, and accessibility. The Walmart and PolicyMe postings show that AI work can involve integrating models into usable products, rather than conducting original research.

Amazon's public search response returned 728 hits for `data engineer`, 2,474 for `data engineer cloud`, and 6 for `data engineer AI` on the research date. ## 4. Compare a location search with remote

The focused data engineering sample contains one Chicago posting (Amazon) and one explicitly remote-US posting (Splice): a 1–1 tie in this small reviewed sample, not a census of all openings. The broader sample also contains remote-in-Ontario work at PolicyMe, which cannot automatically be counted as an opportunity for a US applicant. Veeva's general Work Anywhere policy likewise does not remove its entry-level office requirement.

Neither the Chicago Amazon posting nor the remote Splice posting publishes applicant totals. Therefore I cannot determine which had more applicants. I would record “not publicly available,” rather than treat missing numbers as zero or assume remote roles always have more applicants. The evidence here supports searching both local and eligible remote roles; it does not establish which market has more openings overall.

## Reflection and proposed next steps

This week's project connects Python to APIs, data preparation, model evaluation, and saving a reusable artifact. That makes data engineering and backend development useful paths to explore next. The job descriptions suggest building skill in SQL, APIs, testing, and deployment alongside Python, rather than choosing a permanent specialty immediately.

A concrete next step is to extend the weather project so it stores daily records and predictions in a database, then explain the result through a small API. That would provide evidence of data processing and backend skills. A small frontend could help test whether building user interfaces is also interesting. Comparing those experiences would give a stronger basis for choosing a direction than job titles alone.

The experienced roles in this sample are useful maps of future skills, not evidence that a class project satisfies their hiring requirements. For nearer-term searches, junior, associate, apprenticeship, and internship terms are worth checking, with close attention to degree, experience, and location restrictions. Personal strengths and enjoyment should be assessed from actual project work; these research notes do not establish them.
